## 实现范围

- 默认产品入口使用已确认的主窗、详情、设置、TLS、权限、关于、退出和日志样式；界面仅转发共享 `ProductHost` 动作和快照。`--style-demo` 为独立样式演示，`--product-demo` 为无网络产品演示，二者不当作真实连通性证据。
- 复用原 Agent 的配置、连接、授权、传输目录、Plink SSH 和串口逻辑。传输详情显示 Agent 实际接收目录，完整路径使用原生只读输入框，可水平查看；打开目录失败在界面显示错误。
- Agent 本地事件携带实际 Shell 类型；持久 Shell 从真实资源表继承，SSH 和串口类别优先。没有修改网络协议，也没有从命令字符串猜测分类。
- 同一个只读观察窗接收真实事件；“全部／CMD／PowerShell／Shell／SSH／串口”共用记录和原生 EDIT。选中分类与执行中绿点分别表示查看和后台状态，同类并发显示数量。完成、失败、中断、断连清理活动状态，stderr 不当作结束。
- 暂停只冻结显示，筛选／隐藏不停止任务；新任务自动显示但不抢焦点。历史按 2000 条记录及 262144 UTF-16 单元双重限制，裁剪／漏显数量可见，复用既有脱敏规则和异步剪贴板工作线程。

主要文件：`style_preview.rs`、`style_preview/business.rs`、`style_preview/observer_data.rs`、Agent 的 `lib.rs`／`operation_log.rs`、共享桌面 Host 的 `lib.rs`／`runtime.rs`。Service 仅作新增事件字段的测试兼容。

### 性能与敏感输出报告规则

为完成后续功能步骤，脚本区分critical和quality_only。只有原始schema／检查／指标严格自洽，后台停止、消息循环与清理均成功、活动为0、观察正文核验无错误，且退出1唯一失败精确属于100ms性能检查时，才继续后续功能；保留原 `passed:false`、退出1和失败检查，最终进程仍退出1。崩溃、缺报告、模型不一致、未知失败或指标矛盾一律立即停。27项纯脚本回归覆盖这些边界。

此前最后断言将所有子进程stdout都当成诊断，忽略MCP stdout本来就是授权命令的原始JSON结果通道。Agent `command_summary` 原样返回stdout/stderr，MCP `action_output`原样返回summary；夹具主动打印的合成 `password=…` 必然出现在该协议结果。修正仅作用于测试，不改产品输出契约：真实合成SSH凭据仍全通道禁止，主动标记在任何stderr或非指定MCP stdout也禁止，协议例外按同一个process state对象绑定，参数或字段异常fail closed；窗口仍同时禁止两种标记。定向真实Plink补验确认这一区分，不是删除凭据检查。
