# Windows 原生界面小样评估

## 目标与边界

本小样用于评估 Windows 原生界面与只读操作观察窗的体积、中文呈现、布局、有界日志和退出稳定性。源码位于 `apps/remoteops-agent-native-prototype`，与现有 Eframe GUI 并存，不替换已交付程序，也不改变现有远程协议或权限规则。

主窗口与观察窗采用 Win32 和系统 Unicode Rich Edit 控件，不依赖 WGPU、DX12 或 OpenGL 渲染器。观察窗仅展示后台提交的命令和返回记录，不读取认证输入，也不接管 SSH、串口或 Shell 的标准输入。界面与后台通过有界事件队列隔离；队列满时使用可取消背压等待，不以传输丢行换取响应。窗口关闭时请求停止并等待后台退出。

默认启用 `agent-runtime`，实际引用现有 Agent 核心；`--no-default-features` 构建界面版，用于区分公共运行时与界面自身的成本。界面版不具备真实远程能力，不能以其尺寸代替带核心的最终交付尺寸。默认及 `--demo` 为离线交互；SSH、Console 展示内容须标记为演示，不能当作连接交换机的实测证据。

## 构建与运行

在仓库根目录使用既有 Windows 工具链构建；正式对比时两个版本须使用相同工具链、profile、静态 CRT 和路径重映射设置，并分别保存产物，避免后一次构建覆盖前一次：

```powershell
cargo build --locked --profile release-small -p remoteops-agent-native-prototype
cargo build --locked --profile release-small -p remoteops-agent-native-prototype --no-default-features
```

构建命令本身不代表已经通过 Windows 验收。不要直接把只用于小样的 EXE 混入现有正式发布包。

交互检查可运行 `remoteops-agent-native-prototype.exe --demo`。自测主窗口默认隐藏；观察窗的不激活显示检查可能短暂显示窗口，使用 `--visible` 可显示完整主窗口过程；`--preview-dpi 144` 只作布局预览，不修改系统缩放。

## 自动验收

验收脚本要求 Windows 与 PowerShell 7.2 以上，不需要管理员权限：

```powershell
pwsh -NoProfile -File .\scripts\Test-NativeGuiPrototype.ps1 `
  -Executable .\target\release-small\remoteops-agent-native-prototype.exe
```

可通过 `-OutputDirectory` 指定输出位置，默认在 `artifacts/native-ui-prototype` 下创建含中文和空格的独立目录。脚本复制指定 EXE，使用结构化参数传入同样含中文和空格的报告路径；每轮清理子进程的产品环境变量并隔离用户配置和临时目录。自测不接受真实 Agent 配置，不修改用户系统设置，不连接真实现场。

脚本执行以下检查：

1. 请求生成 100,000 行，限时 90 秒；要求进程退出码为零、报告 `passed=true`、至少 10 项内部检查全部通过，且实际生成和接收数量均为 100,000 行、传输丢行数为零。
2. 连续五轮请求 500,000 行，在 100 毫秒退出时限后请求关闭；每轮仍须正常退出并留下完整报告。每轮实际生成行数须大于零且小于请求总量，确认覆盖输出尚在进行的场景。
3. 每份报告校验保留行数与裁剪行数之和等于已接收行数，历史保留不超过 2,000 行；产生、接收、传输丢行和历史淘汰分别记录：`dropped_lines` 表示未被界面接收的传输丢行，正常压力场景必须为零；`trimmed_lines` 表示已经接收、随后因历史容量上限淘汰的旧行，属于有界显示策略，不是传输丢失。提前退出会取消尚未生成或尚未处理的输出，不要求完整接收或零丢失。
4. 汇总本机墙钟时间、观测到的进程峰值工作集、EXE 字节数、SHA-256 和仅包含一个 EXE 的 DEFLATE `SmallestSize` ZIP 字节数。

汇总报告为本次目录中的 `summary.json`，各轮自测报告和标准输出、错误输出保留在子目录。超时或非零退出均视为失败；清理只针对脚本启动的进程，不停止其他同名程序。脚本不使用 PowerShell UI Automation。

## 验证范围与待测项

小样自测检查中文与补充字符、只读控件、脱敏、有界历史、窗口生命周期、后台停止及逻辑 DPI 布局。96、120、144、192 DPI 的布局注入用于检查尺寸计算和控件边界，不能代替真实系统缩放、跨显示器移动、字体回退和人工视觉检查。

`remote_session` 只说明当前进程是否处在远程桌面环境；未发生实际 RDP 连接、断开与重连时，须记录未测。当前进程处在 RDP 中也不意味着重连行为已验证。未经用户明确允许，不得为验收修改用户系统缩放或远程桌面配置；获准临时调整后须恢复原设置。

自动化压力检查可以发现本机场景的明显卡顿、无界增长和退出失败，不能证明长期内存稳定或覆盖所有 Windows、显卡、输入法与无障碍环境。ZIP 为单 EXE 压缩，不是完整发布包；不同压缩器或参数的结果不得直接归因于界面框架。

## 2026-10-30 本机实测

分支为 `codex/windows-native-ui-prototype`；原有 egui 程序及上一轮未提交的优化改动均保留。小样没有加入正式发布脚本，也没有替换现有入口。

| 程序 | EXE 字节数 | MiB | 单 EXE ZIP 字节数 |
|---|---:|---:|---:|
| 现有 egui GUI | 17,380,352 | 16.58 | 6,971,287 |
| 原生小样，包含真实 Agent 核心 | 6,020,096 | 5.74 | 2,371,397 |
| 原生小样，仅界面与日志/脱敏模型 | 1,500,160 | 1.43 | 589,972 |

上述 ZIP 使用 Python DEFLATE level 9 统一比较，仅包含一个 EXE；与测试脚本采用的 .NET SmallestSize 结果区分。核心版 EXE 相比现有 GUI 减少约 65.36%。引用核心不代表完成所有产品界面：小样尚未移植完整配置、信任确认、现场权限管理和错误恢复交互，也不是全功能替代品。

测试主机为 Windows 11 专业版 10.0.26200，系统 DPI 为 96。默认核心版 12 项单元测试、界面版 11 项单元测试及两组 `cargo clippy --all-targets -- -D warnings` 均通过；两个小样目录通过构建路径脱敏检查。

两种小样均通过一轮 100,000 行完整压力和各五轮输出期间退出。核心版完整压力实际生成/接收均为 100,000 行，传输丢行为零，保留最近 2,000 行、历史淘汰 98,000 行；约 5.49 秒完成，单次 UI 批处理最大 150 毫秒。脚本观察到的进程峰值工作集约 19.3 MiB，仅代表本机离线压力场景。每轮包含 23 项窗口/文本/退出内部检查，均通过。

已验证中文和 emoji 的 Unicode 往返、中文空格文件/报告路径、只读键盘拦截、纯文本而非 RTF 解释、认证内容脱敏、观察窗自动显示不激活、观察窗关闭仅隐藏、十轮重建 GDI 数量有界、后台有界取消和最小客户区布局。已人工检查本机 96 DPI 原生窗口及 144 DPI 逻辑预览，并运行固定本地只读查询验证实际中文输出；SSH/Console 按钮仍为明确标注的演示。

96/120/144/192 DPI 为逻辑布局与最小窗口边界注入，不是物理显示缩放切换。本机 `remote_session=false`，真实 RDP 连接/断开/重连和跨显示器 DPI 切换尚未验证。会话通知仅验证处理路径，不充当真实 RDP 验收证据。

判断：体积收益值得继续验证；在补齐真实 RDP、物理 DPI、产品交互及长时稳定性验收前，保留现有 GUI，不直接迁移生产入口。
## 2026-10-30 真实 RDP 会话补测

通过 RemoteOps MCP 在用户已连接的 CafeCenterNode01 上运行相同 SHA-256 的独立小样；保留旧版 Agent 作为测试通道。两种构建的自测报告均确认 `remote_session=true`，当前实际显示 DPI 为 96（100%）。这补齐了 RDP 会话内执行证据，不能代替断开重连或真实高分屏切换。

| 构建 | 100,000 行墙钟时间 | 最大单次 UI 批处理 | 正常压力传输丢行 | 输出期间退出 |
|---|---:|---:|---:|---|
| 包含 Agent 核心 | 26,917 毫秒 | 400 毫秒 | 0 | 五轮通过，559–590 毫秒 |
| 仅界面 | 26,604 毫秒 | 356 毫秒 | 0 | 五轮通过，516–575 毫秒 |

两种构建均接收 100,000 行、保留最近 2,000 行；完整压力的 23 项内部检查均通过。中文空格路径、Unicode 往返、只读、脱敏、观察窗不激活、GDI 重建与后台退出均有本轮自测记录。主窗口已通过远端截图确认中文呈现正常。提前退出会取消队列中尚未处理的输出，其统计不作为正常场景零丢行结论。

原始报告保存在 `artifacts/native-ui-prototype/rdp-20261030/core-summary.json` 与 `ui-summary.json`。本机与目标机硬件、负载不同，这些时间不是单独量化 RDP 开销的受控对比；但目标机 356–400 毫秒的最大批处理提示大量日志刷新仍有改进空间，不能据通过一秒上限就声称流畅。

后续由用户完成一次真实 RDP 断开重连，核对结果见下节。实际系统缩放/跨屏变化、持续输出期间重连和长期运行仍待验。
### 原生按钮的旧版 UIA 兼容性

用户将小样切到前台后，旧版现场图形 Provider 能枚举原生主窗口和控件名称，但将按钮报告为 `ControlType.Pane`。对“SSH 交互演示”的 Invoke 调用返回“不支持的模式”，焦点加 Enter 回退返回“目标元素无法接收焦点”。因此本轮无法通过旧版语义接口完成按钮自动化；用户已用鼠标成功触发 SSH 演示，随后继续核对窗口和日志。尚不能据此将问题归因于小样或旧 Provider 的某一方，迁移前应补测标准 UIA 客户端和无障碍支持。
### 一次真实断开重连后的核对

用户手动点击 SSH 演示、保持观察窗打开，并报告完成同一目标的 RDP 断开重连。RemoteOps MCP 随后核对：测试进程仍为同一个 PID，主窗口句柄和尺寸保持不变，新增观察窗也属于该进程；观察窗保留五行演示记录、显示 `display version`、中文返回和“身份认证信息已隐藏”。当前前台仍为主窗口。截图未见中文乱码或空白内容。本次结合用户操作确认与重连后状态核对，没有独立采集 RDP 会话事件时间线。

随后仅向路径匹配的测试进程发送正常窗口关闭请求，115 毫秒内退出，成功写入 `rdp-interactive.json`。该报告的五项退出/日志检查均通过；演示生成和接收均为五行、传输丢行为零、最大单次 UI 批处理 29 毫秒。正常退出覆盖本轮重连后的消息循环和后台清理；旧版 Agent 保持运行，测试持久 Shell 已关闭。

证据位于 `artifacts/native-ui-prototype/rdp-20261030/reconnect-evidence.json` 与 `rdp-interactive.json`。程序内的 `rdp_test_status` 是固定提示“重连尚未验证”，它自身不探测或证明重连；本节的人工补测记录单独补充这一事实，不改写原始报告。

本轮结论：真实 RDP 会话内压力/退出测试和一次用户操作的断开重连核对通过。仍未验证持续输出期间断线、反复重连、网络异常、物理高分屏及跨显示器切换。体积收益支持继续试点，但大量日志的 356–400 毫秒批处理和旧版 UIA 接口兼容性都应在正式迁移前处理或明确验收，暂不替换现有界面。

### 实现与定位

日志模型新增呈现游标和 UTF-16 增量补丁，控件只删除淘汰的完整行并追加新文本；暂停、选中复制时保留当前视图，恢复后无需等待新日志即可追赶。重建或完全落后时回退有界快照。Rich Edit 内部单 CR 与模型 CRLF 的位置分别计算，批次关闭重绘，保持只读、脱敏、零传输丢行和最近 2,000 行上限；关闭撤销历史并使用水平滚动避免重排长行。界面每批处理最多 512 个事件、模型排空预算 4 毫秒、计时器间隔 16 毫秒。日志使用覆盖中文的系统字体，减少西文字体在混合中文插入时的回退排版；文本保留原样，比例字体不保证英文表格按字符等宽对齐。

分段测量显示剩余成本集中在 Rich Edit 的文本插入。曾对标准 EDIT 做同机 A/B，它在大量混合中文日志下超过 60 秒，未采用。最终保留 Unicode Rich Edit，不关闭字体回退或削减日志内容。第一次增量版本虽将最大批处理降到 41 毫秒，但总耗时 16.9 秒未过 15 秒预算；进一步调整字体与批次后按原预算通过，失败记录保留在远端本次独立测试目录。

UIA 根因在图形 Provider 的托管客户端初始化：WPF 默认代理加载遍历 PowerShell 动态调用栈时遇到空的 ReflectedType，使标准 Button 退化为 Pane。同一旧 EXE 经原生 CUIAutomation 查询本来就正确暴露 Button/Invoke；修复落在 `remoteops-visual`，通过禁止内联的静态 C# 方法在首次查询前注册系统控件代理，观察、调用和文本输入共用初始化。没有给小样添加自定义 Provider，没有新依赖，现场旧 Agent 仅作为传输/执行通道。修复后的共享初始化脚本在独立 UIA 验收进程中实测；旧 Agent 二进制本身仍包含旧客户端行为，未被本轮热修或替换。

### 最终实测

四组测试均使用最终产物，压力窗口真实可见，最终控件文字逐字等于脱敏后的模型；各组正常产生/接收 100,000 行、传输丢行 0、保留 2,000 行。每组另通过五轮输出期间退出，以及 25 项真实 UIA 调用检查。

| 环境 / 构建 | 100,000 行墙钟耗时 | 最大批处理 | P95 批处理 |
|---|---:|---:|---:|
| 本机 / 包含 Agent 核心 | 11,515 毫秒 | 86 毫秒 | 67 毫秒 |
| 本机 / 仅界面 | 6,835 毫秒 | 31 毫秒 | 27 毫秒 |
| RDP / 包含 Agent 核心 | 12,243 毫秒 | 54 毫秒 | 44 毫秒 |
| RDP / 仅界面 | 11,364 毫秒 | 52 毫秒 | 49 毫秒 |

RDP 核心版最大计时器间隔 62 毫秒，界面版 61 毫秒；`max_tick_ms` 不包含异步 WM_PAINT，间隔指标补充描述消息循环的调度情况。此前同一远端的核心版为 26,917 毫秒 / 最大 400 毫秒，界面版为 26,604 毫秒 / 最大 356 毫秒。新测试要求可见窗口，主机负载不完全受控，这些是实测改善而非隔离 RDP 开销的严格基准。新旧对比未更改输入规模、中文/emoji 内容、历史容量或脱敏要求。

每组正常压力有 41 项内部检查，新增真实窗口的暂停保留、恢复追赶、选中保护、解除选择后追赶、隐藏刷新不弹窗等检查。UIA 每组 25 项检查覆盖七个按钮的 Button 类型与 InvokePattern、真实焦点、禁用连接按钮拒绝、SSH/Console 演示命令和中文结果、不抢焦点、观察窗隐藏重开和正常退出。仅传入 -SkipBootstrap 时同一旧小样仍复现 Pane/无 Invoke 的失败基线；Windows PowerShell 5.1 也单独确认修复初始化后能够识别 Button 和 Invoke。

核心版单元测试 17 项、仅界面版 16 项通过；图形 Provider 17 项通过、1 项交互测试按既有规则忽略。相关 Clippy、格式、65 个 Markdown 链接、差异空白和交付目录路径脱敏检查通过。

### 调查结果与实现选择

稳定连接中的单轮压力不能覆盖交互运行、完整 UIA 访问和同一进程连续多轮压力。Rich Edit 候选曾在前两轮明显改善，后续仍出现刷新退化。对照测试保持 EXE、日志内容、字体和窗口条件不变，仅收窄查找主窗口按钮的 UIA 搜索范围，SSH 后压力由约 22 秒、最大 133 毫秒变为约 11.6 秒、最大 44 毫秒。这说明测试前的 UIA 遍历会影响后续表现，但并未证明具体原因就是 TOM 活动范围或某个内部字体缓存。前置 TextPattern 快照不是唯一触发条件，不能通过不访问观察窗来证明产品修复。

字体/字符集/字号诊断没有观察到显式漂移；纯 Unicode 流式追加、TOM Freeze、暂停撤销以及任务首批重新同步完整快照的候选均未稳定解决问题，未采用。相关候选源码和原始失败记录留在 `artifacts/native-ui-prototype/rdp-dpi-fix-20261030` 的独立目录，不用一次通过覆盖后续失败，也不把 API 替换本身当作根因已查明。

本轮转为使用系统 **Unicode 标准多行 EDIT**，移除 Rich Edit DLL 加载及专属接口。模型与控件都使用 UTF-16 / CRLF 位置，前缀删除不再减去每行一个 CRLF 单元；文本通过 `GetWindowTextW` 读取，显式设置文本容量并清理撤销缓冲，保持只读、系统字体、中文、emoji 和原生 UIA 支持。此前标准 EDIT 在一次性大批插入下的失败仍保留；此次对照结合了分块呈现，不能把不同更新策略的结果简单归结为控件名称。

当前候选实现将接收与显示分开：

- 模型保留最近 2,000 行、最多 262,144 个 UTF-16 单元；仍先脱敏，再截断与保存。
- 每次接收最多 1,024 个事件，仍受 4 毫秒模型排空预算限制；输入队列与可取消背压规则保持。
- 控件每次追加最多 512 个 UTF-16 单元、32 个换行，代理对和 CRLF 不拆开；长单行可以跨片段。完整目标也分块呈现，不一次向控件插入整个历史。
- 连续输出时以 33 毫秒间隔合并过密的新目标；可取代尚未完整显示的过时中间帧。输入停止后，同一目标的剩余片段不再受该节流条件限制，继续通过消息循环追赶。
- 暂停、焦点中的选中复制保护当前视图，解除后无需新日志也能追赶；隐藏观察窗不因刷新重新弹出，重建后从模型恢复。

`received_lines` 表示模型实际接收；`trimmed_lines` 表示已经接收后因历史上限淘汰；`dropped_lines` 表示传输未送达；新增 `coalesced_updates` 表示未完成显示的中间目标被更新目标取代。中间帧合并不等同于传输丢行，也不保证每条高频输出都曾单独画到屏幕。最终最近历史仍须逐字等于脱敏后的模型，不能只用 pending 为零或计数正确代替文本一致性。
