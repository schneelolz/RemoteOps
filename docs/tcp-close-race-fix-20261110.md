# TCP刷新白屏修复交付

## 缺陷与复现

JLAI`.17`、MCP`.29`、Relay`.21`首次打开路由器登录页及多标签页测试曾通过。用户随后手动访问出现白屏，干净Edge复现首次成功、刷新后脚本连接重置、后续本地连接被拒绝。转发关闭原因包含“TCP连接不存在”和“TCP入站窗口队列已满或连接不存在”。前一次验收未覆盖刷新时的连接关闭交错，不能继续作为刷新可靠性通过结论。

连接两端独立结束，可能在状态表移除单连接后仍收到已在传输中的数据、确认或连接回执。旧实现将其判定为整个转发失效，关闭监听和其他连接。

## 修复边界

- 协议`tcp_forward.rs`提供统一的单连接标识读取，消息格式、协议20及TCP扩展v2保持兼容。
- MCP记录本次监听已使用的连接标识，最多65,536个且不复用。Agent和Relay复用已有的有界标识集合。
- 只丢弃同一转发中已经登记并结束的连接帧。未知标识仍被拒绝，当前会话、授权、连接代次和目标策略校验仍在路由之前执行。
- 单连接消费者结束或接收队列超限时，只释放该连接并通知对端。整条传输已断开或关闭通知无法入队时仍按故障关闭转发。
- 配额仍为每条16个、MCP和Agent各32个、Relay总计128个，流控和流量限制沿用。

## 验证

新增确定性Relay测试在旧实现上失败，修复后验证已结束连接的Data、Window、Connected和Closed帧不会关闭监听或其他连接。另测未知连接数据仍拒绝。

三端专项连续80次取消仍有数据在途的下载，同时保留另一条连接持续传输并继续建立新连接，验证监听存活。原大数据、慢读、半关闭、配额、回收、撤权和断线测试继续执行。

最终版本工作区1044项测试通过、6项既有现场项目忽略，格式、检查和严格Clippy通过。Chrome及Edge均通过无请求拦截回归，每个浏览器20次取消导航、10次完整页面刷新和两个额外标签页，稳定加载阶段无失败请求，监听保持存活。另一次六条连接占用叠加高频取消的压力过程触发16连接配额，监听保持存活，测试记录区分配额拒绝与本次误关闭缺陷。

测试驱动曾与共享debug构建同时运行，导致Windows无法替换占用中的EXE；待浏览器进程回收后重新构建并执行三端专项通过。生产切换期间独立MCP初始化超时，服务健康后重新执行Codex/pi两个独立进程验证均通过。
