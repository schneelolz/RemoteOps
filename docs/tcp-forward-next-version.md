# TCP 转发下一版需求记录

记录日期为2026年11月10日。用户要求当前版本暂时保持现状，以下需求与下一版其他修复一起规划和实施。本记录的状态为待设计、待实施。

## 已确认需求

### 持续使用的生命周期

用户期望在现场Agent持续运行、控制端MCP在线及会话授权有效时，转发入口能够持续使用。下一版统一评估空闲10分钟关闭整条转发、单转发累计512 MiB及累计连接标识预算达到上限后的关闭行为，明确单个TCP连接与监听器的生命周期，并保证长期运行时内存和连接记录有界。

断线、撤权、授权失效、Agent退出等清理继续执行。网络恢复后的状态核对、是否需要重新建立监听以及本地端口占用处理需在设计时明确，避免自动重放应用数据。

### 现场Agent查询与独立关闭

- 在现场Agent界面查看当前经过本Agent的TCP转发，包含多个本地监听和多个Controller创建的转发。
- 展示固定目标、控制端监听地址、创建方可识别名称、状态、活动连接数和累计流量等信息。无查询权限的字段按实际权限处理。
- 现场操作者可选择并关闭一条转发，释放相应本地监听、目标连接及三端状态。
- 单条关闭保持其他转发和Agent连接正常，并显示关闭结果与原因。

### MCP查询与独立关闭

- 完善现有 `list_tcp_forwards` 和 `close_tcp_forward`，复用已有工具和状态模型。
- 查询应反映Relay、Agent确认的实际状态，明确本MCP创建的转发与当前已授权会话中其他转发的可见范围。
- 通过稳定转发标识关闭指定转发，返回已关闭、已经结束或结果未知等准确状态。
- Agent界面关闭后，MCP查询及时反映状态，MCP关闭后，Agent界面及时反映状态。
- 多Controller之间的查询范围、关闭权限和脱敏字段在设计时单独确认。

## 协调边界

涉及共享协议、Relay权威转发状态、Agent运行时与界面、Controller应用层和MCP工具，实施前统一确定状态字段、通知和兼容规则。现有MCP进程内列表仍是当前能力基线，跨进程、跨Controller视图需明确能力协商及旧版本降级行为。

每条16连接、MCP与Agent各32连接、Relay总计128连接及目标白名单、权限、速率、背压规则继续作为设计基线。生命周期和资源策略的变更在实施计划中明确。

## 后续验收

- 长时间空闲后继续访问，累计大流量与大量短连接后入口仍符合新的生命周期策略。
- 多条转发并存，Agent界面与MCP查询和关闭指定条目，其他条目继续工作。
- 单连接结束、半关闭、迟到帧、重复关闭、并发关闭及查询期间状态变化。
- Agent、MCP、Relay断线，撤权、权限变化、目标规则撤销及重连后的状态核对。
- 多Controller可见范围、跨会话隔离及关闭权限。
- 真实网页、SSH及RDP分别记录实际验收结果。

## 当前处理决定

当前上线代码和资源限制先保持现状。目标规则可配置为不自动到期，监听仍受当前进程、会话、权限和资源限制约束。本记录归入下一版，后续先制定实施计划再修改与验证。
