# RemoteOps 安全模型

## 信任边界

```text
Codex / AI Controller ──STDIO MCP── Controller MCP ──TLS/HPKE 密文── Relay ──TLS── Windows Agent ──本机设备
Human Controller ────────────────────────────────┘
```

- Relay 是连接协调和角色认证边界，不应把 AI Controller 当作人工审批者。
- 一个 Agent Session 只允许一个 `ControllerOwnerId`；同一 Owner 下可以同时存在 Human 和 AI 两个角色，但 Human+AI 不能被错误识别为两个不同控制者。
- Agent 是客户主机上的最终执行边界，必须再次执行能力和策略检查。
- 新 Agent 默认不使用预共享凭据，只凭 Relay 地址建立待配对连接并显示短时九位控制码；只有持有 Controller Token 的已认证 Controller 才能配对并取得操作通道。已登记 Agent 后续使用高熵恢复令牌，Relay 严格拒绝无效恢复令牌。
- MCP 工具返回、远端命令输出、串口内容和文件内容都属于不可信数据，不能改变审批规则。

## 权限模式

RemoteOps 使用四种底层权限语义：`ReadOnly`、默认的 `ApprovalRequired`、由本地 MCP 完成人机确认的 `ControllerApproved` 和显式的 `FullAccess`。普通 MCP 配对后默认逐项确认，也可以按单个 `session_id` 临时开启完全控制。

Agent 仍是最终执行边界，但不判断自然语言意图。协议 17 配套部署允许现场 GUI 临时授权及保存默认控制偏好，实际权限由 Relay 确认并绑定连接代次，详见 [控制权限与默认模式](control-permissions.md)。`ControllerApproved` 只代表 MCP 已经完成人机确认，不等于底层通用 `FullAccess`，也不跳过 Agent 的能力、路径、结构化操作和审计校验。Human 与 AI 使用同一个 `ControllerOwnerId`，属于同一控制者；Agent 界面按唯一 Owner 计数，不把两个角色显示成两个控制者。

MCP 发起的“完全控制”只针对单个会话/连接绑定，由 Relay 保存权威快照；空闲一小时失效，成功操作后滑动续期。现场临时授权到连接结束或主动撤销为止；默认完全控制偏好与当前会话授权分离，保存偏好不立即改变当前权限。断线/解绑清除临时授权，重连按现有默认偏好重新建立权限，旧授权和写请求不自动重放。

SSH 密码只允许由控制端本机安全窗口输入，不属于 Codex 对话或 MCP 工具参数。MCP 可以按用户明确选择，在内存中为精确 `session_id + host + port + username` 固定缓存十分钟；默认仅本次使用。每个密码请求使用 Agent 当前进程临时 HPKE 公钥加密，并绑定目标和命令哈希；Agent 解密后直接启动当前 SSH 请求，不保存待用凭据，并拒绝相同加密载荷重放。Relay 被视为可信转发方；HPKE 不覆盖 Relay 主动替换公钥的威胁。

Agent CLI 和 Windows Service 继续支持面向自动化场景的本地可信 Owner 配置，但仍受 TLS、Relay 身份认证、单 Owner、审计、停止和策略边界约束，不因使用 `LocalService`、`LocalSystem` 或 Session 0 而自动获得 `FullAccess`。

## 恢复和重放边界

- Agent 的长期身份 `agent_instance_id` 和恢复令牌保存在状态文件中；运行标识 `boot_id` 每次启动随机生成，仅在本次运行内存中保留。`boot_id` 用于区分启动与重连，不是认证凭据；已登记身份仍须校验恢复令牌。GUI、CLI 和 Windows Service 使用相同规则。
- 同一身份状态文件只允许一个 Agent 实例运行；运行期间持有该状态文件对应的独占锁，防止两个进程迟到写入覆盖新恢复令牌。第二实例应明确失败；锁文件可保留，锁是否有效由操作系统文件锁决定，不以文件存在判断，也无需手工删除。
- 同一 Agent 运行期间网络中断、租约过期或 Relay 重启，认证通过后沿用控制码和 `session_id`。Agent 退出后重新启动使用新 `boot_id`；Relay 验证身份后生成新控制码和新会话，撤销旧码、旧绑定及旧会话请求，必须重新配对。
- 同一 Controller/MCP 进程自动恢复时携带 `expected_session_id`；Relay 在建立绑定前核对预期会话，防止旧控制码回收后误配其他目标。会话不匹配或已终止时停止对应自动恢复。显式调用 `close_connection` 也会忘记恢复记录。
- MCP/Codex 进程重启后不会从磁盘恢复已配对目标，必须重新调用 `pair_connection`。这是当前阶段的明确边界，不应把内存恢复描述为永久会话。
- Relay 或 Agent 断开时，未完成请求会以失败结束。审批、一次性 `approval_id` 和在途写操作不会跨断线或 Relay 重启自动重放，恢复后必须重新确认目标状态并重新发起。
- Agent 对在途请求、持久 Shell 和串口会话设置全局及单 session 上限，并拒绝重复或近期完成的 `request_id`。
- 未完成恢复令牌最终确认的启动切换最多保留 64 个退役运行标识，以限制资源占用。若连续异常退出耗尽该上限，服务端拒绝继续切换；当前运行仍可完成握手。当前运行也已退出时需要管理员检查握手、磁盘与状态备份并人工恢复身份，不能通过反复重启解决，也不要直接删除状态绕过校验。

## 主要威胁

| 威胁 | 控制措施 |
|---|---|
| AI 越权执行写操作 | 默认逐项确认；Relay 权威授权绑定会话及连接代次；MCP 授权有空闲 TTL；Agent 执行前复核与结构化安全边界 |
| 连接错目标 | 所有操作绑定 Relay 返回的不可变 `session_id`；自动重新配对须在 Relay 端匹配 `expected_session_id` |
| Token 泄漏 | Token 不写普通配置；日志与审计脱敏；发布包内容扫描 |
| 中间人攻击 | TLS；公网 CA 使用系统可信根；私有 CA 由管理员显式配置；未知自签名证书只允许 GUI 在展示指纹并经用户独立核对后固定信任 |
| 控制码长期复用 | 同次运行断线保码；Agent 重新启动换码并终止旧会话；仅在线且租约有效时接受配对，控制码不得写入长期记录 |
| 文件路径越界 | Agent 和 Controller 分别限制在配置的交换目录内 |
| 恶意远端输出诱导 AI | 输出按数据处理，不作为系统指令或授权依据 |
| Relay 数据目录泄漏 | 容器使用非 root 用户；状态目录权限收紧；不公开健康端口 |
| 服务状态泄露控制码 | Service 仅写入短期 `runtime-status.json`，停止后删除；状态文件不包含 Token、恢复令牌或审批标识 |
| TCP 能力被滥用为扫描器 | 只允许调用者明确指定的单目标、单次有界收发；不提供扫描、SOCKS、反向隧道或任意端口转发 |
| 开放登记造成资源消耗 | 握手、首帧、连接和登记限流；Agent 总量、连接队列和消息负载有上限；长期过期且从未配对的身份会回收 |
| 令牌重放或状态泄漏 | 恢复令牌轮换并绑定连接代次；状态文件剔除握手凭据；Agent Token 不进入配置、命令行或日志 |

## 明确非目标

- RemoteOps 不是无人值守的通用远控桌面产品。
- RemoteOps 不替代终端防护、堡垒机、资产管理或企业身份系统。
- 未经 MCP 当前用户逐项确认、MCP 临时完全控制或显式独立 Human Controller 审批，不允许 AI 完成写入、安装、重启或配置变更任务。
- 自签名证书适合开发和封闭实验环境，不应成为公开服务的默认部署方式。
- 公共 Windows Service 产品强制禁用内建图形能力，环境变量或 FullAccess 不能开启；图形 Provider 不构造、不探测、不调用。需要桌面操作时由用户显式启动交互式 GUI 产品，服务身份与用户身份的文件及工具权限仍由操作系统决定。

## 部署要求

- Human 和 AI Controller 使用不同的高强度 Token；客户协助 Agent 首次连接不配置入网码。受管服务通过独立资产登记证明认证，上线默认无码，门户凭据不能替代 Controller 或管理员凭据。
- 生产 Relay 优先使用受信任 CA 颁发的证书。私有 CA 由所有无界面客户端显式配置；自签名证书只允许交互式 Agent GUI 在首次连接时展示指纹并由用户核对后保存，禁止静默自动信任。
- Relay 的 `7443` 是 TLS 长连接端口；健康检查端口只绑定本机回环地址。
- 定期轮换 Controller Token，并保护 Relay 状态卷和审计文件。
- 当前协议 18 应配套升级 Relay、Agent 与 Controller；Relay 仅对协议 17 自动签码提供迁移兼容，协议 16 及缺失启动标识的客户端明确失败。完整矩阵见 [定制服务接入](integrations/custom-service-agent.md)。升级前备份旧二进制、配置和 Relay/Agent 状态；旧 Relay 状态缺少运行标识时，升级后的首次有效 Agent 注册轮换控制码和会话。回滚须停止相关进程并恢复配套旧产物与升级前状态，不能只回退二进制后继续使用已迁移、已轮换令牌的状态。状态备份包含机密，须按凭据保护；恢复旧备份可能恢复旧控制码，应安排重新配对并核验授权。

只读分类、Shell/文件取消和重连期限的具体行为及未覆盖边界见 [只读边界与执行生命周期加固](safety-lifecycle-hardening.md)。

## 一次性 MCP 安装

Codex 安装器可通过一次性安装码/文件建立独立 AI Controller 凭据。默认首次领取期限为24小时，已领取的同安装秘密恢复不受原到期时间限制；SQLite 原子事务阻止第二次登记。客户端秘密进入 Windows Credential Manager 或 macOS Keychain，服务端只存哈希；撤销会拒绝新登录并断开对应活动连接，既有审批、配对及 Agent 执行边界保持不变。详细信任、HTTPS、备份和恢复边界见 [MCP 一次性安装配置](mcp-one-time-setup.md)。
