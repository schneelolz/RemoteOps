# RemoteOps 文档维护规范

## 一、文档类型

| 类型 | 用途 | 维护要求 |
|---|---|---|
| 当前使用手册 | 安装、启动、操作和排障 | 参数和版本必须与当前产物一致 |
| 部署/验收手册 | 环境搭建、自动化回归、停止和回滚 | 命令必须可复现，明确正式与实验端口 |
| 功能索引 | 功能、代码路径、入口和验证映射 | 代码文件变化时同步更新 |
| 交接文档 | 当前结论、阻塞、下一步和安全边界 | 只保留仍有效的当前状态，历史细节链接到验收报告 |
| 验收/阶段报告 | 保存特定版本的证据 | 视为历史快照，不随当前参数反复改写 |

## 二、事实优先级

1. 当前源码、Cargo 配置、构建脚本和实时环境；
2. `docs/README.md` 和当前使用手册；
3. 当前交接文档；
4. 阶段验收、设计和实施历史。

文档与源码不一致时必须先核对实际行为，再更新文档；不得用历史验收报告反向覆盖当前实现。

## 三、命名和状态

- 当前手册使用稳定名称，不在文件名中堆叠版本号。
- 特定阶段证据使用“第一阶段”“验收报告”“交接文档”等明确标识。
- 文档顶部应说明版本、日期或适用范围；过期参数必须删除或明确标为历史示例。
- 同一安装流程只保留一个首选入口，其他文档链接过去，不复制整段步骤。

## 四、安全与链接

- 禁止记录密码、Token、API Key、私钥、真实控制码和恢复令牌。
- 使用相对链接连接仓库内文档；移动文件前先检查所有反向链接。
- 发布包 README 必须包含版本、安装前提、完整性校验、卸载方式和安全边界。

## 五、当前整理策略

现阶段先通过文档中心分类和生命周期标注消除歧义，不批量移动历史文件，避免破坏已有外部链接。后续只有在链接检查工具和发布流程稳定后，才将历史报告物理迁移到 `docs/history`。
