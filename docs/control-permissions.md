# 控制权限与默认模式

适用范围：协议 16 的 Agent GUI、MCP 与 Relay 配套部署。更新日期：2026-09-29。旧部署不支持现场授权入口，不能仅替换 Agent 就宣称状态同步与授权功能已完成升级。本文说明本次实现的行为契约，实际测试及生产部署状态以交付记录为准。

## 当前权限与默认偏好

全新 Agent 和缺少默认字段的旧配置均采用“逐项确认”。“默认控制模式”使用 AgentConfig 配置文件中的 `default_full_control` 布尔字段保存，缺省为 `false`（逐项确认），使用原子保存；保存失败会返回错误，不得显示已保存或据此开启自动授权。它不保存到窗口布局存储。会话授权和自动授权抑制标记只在内存中存在。

设置默认完全控制前，需要现场确认一次：今后成功配对的控制方将在新连接及重连时自动取得完全控制。修改默认值不改变当前连接的权限；当前连接请使用主界面的“控制权限”。

| 情况 | 实际行为 |
|---|---|
| 默认逐项确认 | 新连接、重连采用逐项确认 |
| 默认完全控制 | 每个成功建立的新绑定自动创建完全控制授权 |
| 现场临时完全控制 | 当前连接有效，断线、解绑、控制方变化后清除 |
| 现场切回逐项确认 | 撤销双方完全控制，并抑制本次 Agent 运行期间的后续自动授权 |
| 撤销后手动再授权 | 可以开启当前连接的完全控制，但不会解除自动授权抑制 |
| 重启 Agent | 重新按已保存的默认设置执行 |

未连接时显示“等待连接”，默认偏好不代表权限已生效。既有可信 Owner 设置不会自动迁移为默认完全控制。

## 双端授权与显示

MCP、现场临时授权及现场默认授权统一由 Relay 确认，绑定会话、Agent 连接代次、控制端实例及代次。每次变更带旧快照进行比较，Relay 发布同一份有效模式、来源、修订号和到期信息。旧代次、旧修订号及冲突变更不能覆盖新的撤销。

- MCP 开启完全控制：空闲一小时到期，成功操作续期。
- 现场临时或默认完全控制：到对应连接结束或主动撤销为止，无 MCP 一小时空闲到期限制。
- 现场授权确认后，MCP 不再发起 RemoteOps 内部逐项审批。
- 同步期间显示“正在同步”；5 秒未确认显示失败，可重试，不能提前显示授权成功。
- 文案区分“现场授权”“默认设置”“控制端授权”；未知状态不能当作完全控制。
- 配对、查询、重连取得当前快照，心跳核对并补同步。旧的 `controller_control_mode` 展示字段不作为执行依据。

修改请求携带审批时取得的授权快照和依据。Relay 与 Agent 在执行前检查；被撤销的旧请求不可执行，失败写操作不自动重放。撤销不强行中断已开始的操作。单项确认与独立 Human Controller 审批路径仍受连接绑定和修订号约束。

旧 `--command-mode full-access` 在协议 16 中仅表示允许完全控制的上限，实际操作仍须取得 Relay 确认的有效授权，不再因启动参数而直接跳过审批；现场撤销后不能靠此参数自动恢复授权。建议使用默认 `agent-controlled`，由现场保存默认偏好。

只读、强制外部审批配置仍然是上限。免除 RemoteOps 内部审批不等于免除 Codex 宿主独立的工具授权，也不扩大用户原始任务范围。

## 同步故障与升级检查

先核对实际运行路径、文件版本、构建时间和 SHA-256，再检查 MCP 上报、Relay 接收/转发、Agent 接收和 GUI 应用。版本字符串相同不代表产物相同。日志记录脱敏的失败、恢复和修订号，不记录令牌或真实控制码。

2026-09-29 本机只读核查发现，运行中的 MCP 为 `0.2.0-preview.11`，文件时间为 2026-09-22；工作区最近构建的 MCP 虽然版本字符串相同，但文件时间为 2026-09-26，SHA-256 不同。运行文件缺少新控制模式展示字段的字符串，而本地构建包含这些字段。这确认本机运行产物未替换为最近构建，支持部署不一致的判断，但不能单独证明整个链路的唯一断点。本次未连接或核验生产 Relay，不能声称它已经更新。

交付必须包含同一构建批次的 Agent GUI、MCP、Relay 及哈希清单。协议不兼容时明确提示更新，不将缺失字段解释为授权。替换 MCP 文件后仍需重启实际宿主连接，已经运行的进程不会自动加载新文件。生产 Relay 更新按独立部署安排执行，明确中断范围及回滚产物。

## 验收清单

运行 `pwsh -NoProfile -File scripts/Test-ControlPermissions.ps1` 可构建并启动专属回环 TLS Relay。第一部分用协议模拟 Agent 验证配对逐项确认、MCP 授权、现场撤销与旧凭据拒绝、请求转发，以及真实 TLS 断线重连清除临时授权；第二部分启动真实 MCP 和 Agent，验证默认两种模式、默认完全控制在解绑重配后重新授权、现场撤销后重配仍为逐项确认、现场重新授权及临时目录实际写入。脚本使用随机端口、临时凭据和独立目录，结束后清理自有进程和目录。真实 MCP 客户端不提供逐项确认，因此可核验无授权写入被拒、现场授权后不再需要 RemoteOps 确认。此测试不替代原生 GUI 操作、真实 Codex 宿主审批或生产现场验收；真实 Agent 的网络中断重连仍需现场验证。

- 默认值兼容旧配置，持久保存成功/失败、重启与原子替换正确。
- MCP 开启、现场撤销、现场临时开启后，两端模式和来源一致；修改操作遵循实际模式。
- 默认完全控制在新绑定、重连时重新授权；手动撤销后的本次运行不自动重新授权。
- 延迟确认、旧心跳、旧请求、换控制方、连接重建、并发变更均不能恢复已撤销授权。
- MCP 到期和成功操作续期、只读及外部审批上限、旧协议失败正确。
- 中英文及明暗主题下文字、状态和按钮无裁切；每个现场验收阶段同时核对 MCP 返回、Agent 截图和可清理的测试写操作。
