# Win32 / Slint 现场预览使用说明

本轮提供两个独立的 0.3.0 预览入口，用于比较界面和验证同一份业务核心。旧版继续保留，不替换安装，不切换默认入口，也尚未决定正式迁移。

## 运行方式

1. 将 `Win32` 或 `Slint` **整个文件夹**复制到现场机器的固定位置；不要只复制主 EXE。保留随包 `tools/plink.exe`、其许可及 `remoteops-ssh-askpass.exe`。
2. 分别启动 `Win32/RemoteOps-Win32.exe` 或 `Slint/RemoteOps-Slint.exe`。首次填写现有 Relay 地址；遇到未知证书时，先通过可信渠道核对指纹。
3. 等待窗口显示临时控制码。先测一版，再测另一版，给工程师说明当前使用的是 Win32 还是 Slint，避免把旧版控制码混用。
4. 工程师连接后按当前权限执行测试；需要完全控制时，由现场人员确认。命令结果在只读观察窗展示，关闭观察窗不会停止当前任务。
5. 完成后从主窗口退出并确认，核对程序确实退出。不要在 RDP 测试或缩放未安排时自行改变测试条件。

两版默认使用不同的配置、身份状态和界面偏好目录：`%LOCALAPPDATA%/RemoteOpsNativePreview` 与 `%LOCALAPPDATA%/RemoteOpsSlintPreview`。显式 `--agent-config PATH` 可指定独立配置，但不要让两版指向同一份身份状态。它们仍使用既有每用户 SSH 主机密钥信任库；界面隔离不代表 SSH 信任记录也分离。

在“连接详情”中查看实际配置路径、文件交换根目录，并可打开接收目录。上传回执中的远端绝对路径是现场工具的实际位置；控制端临时路径不是 Agent 路径。不要凭文件名猜测上传位置。

## SSH 与观察窗

普通命令、SSH exec 和串口事件由同一个 Agent 核心进入观察窗，显示实际命令及返回结果，认证信息脱敏。观察窗为只读，不提供命令输入，也不是完整交互式终端。SSH 当前使用 Plink exec / 无 PTY；某些交换机仅支持交互式 Shell 的情况仍需要现场验证。

SSH 未信任主机密钥时会拒绝连接，并返回核对入口；从可信渠道核对后再保存精确指纹。密码通过安全窗口输入，不发到聊天、命令行或配置文件。

另保留独立的 `Console/remoteops-agent.exe` 作为无 GUI 入口。测试它时必须传入 `--config` 指向单独配置，并在该配置中隔离 `state_file` 和 `transfer_root`；不要无参数启动，否则会沿用通用 Agent 的默认配置与环境变量，可能读到旧版身份。图形前端没有实现 `--cli` 参数；其他运行参数以 Console 程序 `--help` 为准。

## 测试边界

本机测试结果绑定到交付清单中的 EXE SHA-256，详细结果见同目录验收记录。演示窗口只用于布局测试，不能代替 Relay 配对和实际命令验收。

真实交换机、物理串口及原先特殊环境仍待现场联调；RDP 断开重连与 100%→150%→200%→100% 缩放按用户要求继续暂缓。未验收项不能引用旧构建的通过结果。

Slint 使用固定的 1.18.1 和 winit 软件渲染。其 timer 耗时不包括实际绘制，不能与 Win32 的呈现耗时直接比较。两版的体积应同时比较主 EXE 和完整运行目录。

## 许可与源码

RemoteOps 原有 AGPL-3.0-only 保持不变；Slint 按其 GPLv3 选项组合，保留官方 AboutSlint 及随包许可。PuTTY/Plink 使用其 MIT 许可。署名窗口不是其余分发义务的替代；`Corresponding-Source.zip` 和 `source-files.json` 提供本次源码快照、锁文件、构建脚本和摘要，现场凭据和身份文件不在其中。首次重建需要 Rust 1.95、MSVC C++ 构建工具及 `cargo fetch --locked --target x86_64-pc-windows-msvc` 获取锁定依赖，再在 C 盘设置 `CARGO_TARGET_DIR` 并运行 `scripts/Build-UiComparison.ps1 -OutputDirectory <不存在的新目录>`。Plink 固定版本来源由 `-PlinkSourcePath` 指定。具体许可依据见随包 `许可与验收.md`。
