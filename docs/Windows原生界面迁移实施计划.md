# Windows 原生界面恢复与共用操作观察窗实施计划

状态：2026-10-30 已获用户确认，两个阶段实现已落地，2026-10-31 最终本机验收通过；交付与仍待现场验证项见[产品预览验收](Windows原生产品预览验收.md)。沿用 `codex/windows-native-ui-prototype` 分支；保留旧版入口与可执行文件，不提交、合并或推送。RDP 与本机缩放测试仍按用户要求暂缓，本轮不自行恢复。

## 目标与范围

使用现有 Win32 原生界面方案，恢复旧 GUI 的布局、中文文案、状态与操作流程；主窗口继续采用旧版的连接状态、设置菜单、大号控制码及复制、倒计时、活动状态、查看连接详情、实时日志、停止协助／退出结构。Windows 原生控件的边框、按钮等细节允许与 egui 有差异，尽量保持原来的尺寸、配色、层次与使用习惯，不承诺逐像素一致。

所有经 RemoteOps 执行的普通一次性命令、持久 Shell 命令、CMD、Windows PowerShell、PowerShell 7、SSH 和串口操作，共用一个只读操作观察窗，显示实际命令、输出、错误、连接与认证状态及真实完成结果。主窗口不承担终端输入功能；观察窗自动出现、不抢焦点，支持暂停跟随、选择复制、手动重新打开。用户关闭观察窗不终止任务，同一任务不反复强制弹窗。

## 第一阶段：恢复原生产品界面

对照 `apps/remoteops-agent-gui/src/lib.rs`、`appearance.rs`、`activity.rs` 和 `extension.rs`，在原生宿主恢复：

1. 首次 Relay 配置、产品固定端点限制、配置错误及保存连接流程。
2. 连接／等待／受控／重连／失败状态，控制码复制与反馈、期限和过期状态；续期使用实际 LeaseRenewed 事件，不增加旧版没有的手动续期动作。
3. 中文／英文、跟随系统／浅色／深色、偏好保存及版本信息。
4. TLS 信任的取消、仅本次允许、保存信任及保存失败提示。
5. 当前控制权限、来源、逐项确认／临时完全控制、默认权限及相应确认、超时与失败结果。
6. 连接详情、提权状态、交换目录、能力展示；运行期连接详情保持只读，不凭空扩展为 Relay 编辑器。
7. 活动摘要、实时日志的历史查看与筛选、未读提示、停止与退出确认。

继续复用 Agent 核心、配置、产品标识、国际化、权限与审计 API。将与 egui 无关的呈现状态独立出来，原生宿主不直接依赖旧 GUI crate，以免把 eframe/wgpu 重新带入包体；连接与权限规则保持在已有核心中。

主要文件边界：`apps/remoteops-agent-native-prototype/src/win32.rs`、`backend.rs`、`model.rs` 及新增职责明确的窗口／呈现状态模块。旧 GUI 目录用于对照和必要的公共状态复用整理，不覆盖已交付旧 EXE。

## 第二阶段：接入真实共用观察窗

优先复用 Agent 的本地 OperationLog、OperationStateChanged 和已有输出分片，保留连接 epoch、会话与 request_id。观察记录统一包含来源、时间、任务／会话、发送／输出／错误／状态；并发操作清晰标记，不能把 stderr 当作执行结束，也不能把收到请求写成已执行。

已经确认必须处理的真实链路问题：

- 普通命令与持久 Shell 已有输出分片，可在现有路径接入。
- 当前 SSH Provider 丢弃流式 receiver，Agent 只取得最终结果；必须打通实际流式读取，换界面本身不能使 SSH 实时。
- 核心本地日志每请求／每输出流超过 128 行后省略。取消此限制前，先处理 Agent 到界面的无界事件积压：使用有界展示订阅／合并与明确的滞后提示，关键执行状态不被高频输出挤掉，后台执行不因 UI 堵塞；即使不显示某些中间帧也继续更新脱敏状态。随后改为持续更新的有界滚动展示，明确提示历史裁剪，避免无限内存和磁盘增长。
- 串口需要按长期 serial session 保留解码与脱敏状态，而不是只跟 OpenSerial 请求的结束绑定；补齐跨读取块的中文 UTF-8、密码／私钥与提示符边界，关闭时正确收尾。
- 密码、私钥、令牌在进入界面和导出前隐藏，认证阶段展示真实状态；无换行提示符需要兼顾及时显示与跨分片脱敏，不能直接把原始分片绕过行缓冲送进界面。不使用演示内容代替真实命令或回包。
- 接收、执行状态与 UI 分批刷新分开处理，保留取消和退出的响应能力。默认保留有界观察历史，不自动产生无限落盘日志。

修改边界：`apps/remoteops-agent/src/operation_log.rs`、`apps/remoteops-agent/src/lib.rs`、`crates/remoteops-device/src/lib.rs` 及其 SSH／串口实现，原生界面的 `backend.rs`、`model.rs`、`win32/log_view.rs`。优先保留现有远控线协议和执行权限链路；公共接口变更需明确兼容方式，不因界面需要另造执行体系。

Plink 沿用此前已选的随包集成方案，不内嵌源码；正式接入时补许可、版本／哈希、进程启动、实时标准输出／错误、安全密码传递和退出清理。按需下载工具的资源库方案仍为后续分发评估，不混入本轮主窗口恢复。

## 验证和交付

- 每阶段独立构建可运行新版，保留旧版，并按旧功能清单逐项对照；编译缓存和测试临时文件继续放 C 盘，D 盘只保留必要交付与证据。
- 单元测试覆盖事件顺序、并发任务、重连旧事件隔离、权限／TLS状态、分片解码与脱敏、超过 128 行持续输出、取消和关闭。
- 本机实际 CMD／PowerShell 输出；可控 SSH 测试端或模拟 Plink 子进程验证流式读取，真实现场 SSH／串口在环境可用后验证，模拟不替代现场通过。
- UIA、中文／emoji、只读、复制与暂停、自动出现不抢焦点、连续多轮大量日志、退出稳定性和最终体积回归。
- 保持现有 100 毫秒批处理、每十万行 15 秒及实际窗口文本等于模型的门槛。
- 最新构建的真实 RDP 断开重连和 100%→150%→200%→100% 按用户方便的时间另做，先 RDP 后缩放；未完成前明确标注待验，不正式替换旧版。

## 验收完成后的迁移判断

以完整功能新版的实际体积、旧版功能对照、真实命令链路和全部待验结果决定是否切换默认入口。现有 5.77 MiB 小样不代表功能恢复后的最终体积，不提前保证该数字保持不变。
