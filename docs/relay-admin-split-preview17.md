# Relay 管理前后端分离与工具中心调整

2026-11-06 已部署。范围仅包括 Relay 后端与管理前端；Agent、MCP、Skill、通信协议和已有授权保持不变。未执行 Git 提交、分支、合并或推送，实施前已有改动保留。

## 版本与结构

| 组件 | 已部署版本 | 职责 |
| --- | --- | --- |
| Relay | `0.2.0-preview.17` | Rust / Axum，提供管理 API、认证与原远程连接服务 |
| 管理前端 | `0.1.0` | Vue 3、TypeScript、Vite、Vue Router；独立静态产物与 Nginx 镜像 |
| 通信协议 | `20`，保持原值 | 保留已有版本及能力检查 |

生产前端源码为 `relay-admin`。各页面、弹窗和表格迁为 Vue 组件，不使用 `v-html`、内联事件、运行时模板编译或旧原型页面套壳。TypeScript 覆盖组件、路由、界面模型和构建配置；原有业务操作继续保留为 JavaScript，并按状态、通用操作、MCP 接入、工具目录拆为独立模块，保留请求代次、写入确认、权限与凭据生命周期逻辑。历史 `relay-admin-prototype` 保留原内容，仅增加迁移说明，不再作为生产入口。

Relay 已删除管理页面的 `include_str!` 和静态路由，根路径、旧 JS/CSS 路径返回 404。管理地址保持 `https://remote-ops.izyfarm.com/`，前端容器提供页面并通过内部服务网络转发 `/api/*`；浏览器继续使用同源 HttpOnly Cookie。后续前端可独立构建和发布，不要求重编译或重启 Relay。

生产管理入口仍绑定宿主机回环 `18081`，后端管理 API 改为回环 `18082`。原公网 TLS `7443`、健康检查 `18080` 和数据卷保持不变。Nginx 以 `101:101` 运行，根文件系统只读、能力全部移除，仅 `/tmp` 使用受限 tmpfs。HTML 不缓存，带内容摘要的静态资源长期缓存。

## 界面调整

- 工具中心分为“全局设置”“工具列表”“节点同步状态”，默认进入列表；手机端提供页内子导航。
- 节点页展示当前目录应用状态，不是下载进度或历史记录。支持名称／标识搜索、状态筛选、25 条分页、固定表头和独立纵向滚动；手机改为卡片。
- 后端新增 `sync_status`：旧端、离线、应用失败、已同步、目录待更新、等待确认分别判断，旧字段保留。仅比较修订号不再足以显示“已同步”。
- 工具编辑改为“基本资料”“版本与平台包”“高级定义”页签。版本页汇总包与验证信息，高级页保留 JSON 和按需展开的启动示例。草稿跨页签保留，保存校验自动定位错误页签，标题、页签、操作按钮固定。
- 迁移概览、会话、节点、MCP 接入、身份、安全设置及审计页面，保留列选择、节点批量关闭确认、紧急停止、一次性设置、改名、撤销、工具管理授权、包上传、测试登记和 CSV 导出。

## 生产部署与核验

- 后端镜像：`remoteops-relay:0.2.0-preview.17-p20-admin010-20261106`。
- 前端镜像：`remoteops-relay-admin:0.1.0-20261106`。
- 备份：`/opt/remoteops/backups/remoteops-before-preview17-admin010-20261106`，包含原 Compose、环境文件、完整数据卷归档、旧镜像记录及回退脚本，敏感文件权限为 `600`。
- 首先在临时前端容器中只读验证代理。固定预检端口被占用时改用 Docker 自动分配回环端口，未占用或重启其他业务；失败预检证据保留。
- 停止 Relay 后完整备份，在无网络的隔离数据副本运行新后端；所有数据库内容摘要／计数和 schema 保持一致、完整性检查通过，再切换两个容器。
- 两容器均 `healthy`、重启次数 `0`。原后端运行环境、身份配置、数据卷及原业务端口保持；工具目录仍为修订 `11`、两项工具，工具定义与全局说明摘要一致。
- 15 份已部署静态文件逐一与交付产物摘要一致，9 个已认证只读管理 API 通过，未认证 API 返回 `401`，后端根路径返回 `404`。
- 公网业务 TLS `7443` 系统信任和主机名验证通过，协议 `TLSv1.3`；公网管理 HTTPS 返回新版 Vue 入口并携带 CSP。
- 核验时 267 个节点中，264 个旧端标为需要升级 Agent，3 个已确认目录同步。这是当时的状态快照，不是本轮升级现场 Agent；日志仍有既有旧端上下文校验与不完整 Hello 错误，分类复核无其他错误和 panic。

## 后续发布与回退

前端入口为 `scripts/Build-RelayAdmin.ps1`，后端入口为 `scripts/Build-LinuxRelay.ps1`。前端包记录自身版本、最低后端版本、锁文件、许可证和文件摘要。禁止同版本覆盖不同产物，后续修改分别递增对应组件版本。

`scripts/relay-admin-rollout.py` 保存本批首次拆分的完整编排、备份及失败恢复方式，批次和版本是本次固定值，不可作为后续版本不修改即重复执行的通用命令。回退先停止新前端、恢复本次备份的 Compose／环境文件，再重建原 Relay；本批不改变数据库 schema。失败镜像、容器、日志、备份均保留。

生产管理员原登录会话可能因后端重启失效，重新登录即可。Agent、MCP、Skill 无需重新安装。旧 Agent 的能力不足不会通过页面更新消失；本批未升级这些客户端，也未登记新的平台测试通过。
