# 公开资源仓库协议 v1

资源仓库是一个普通 HTTPS 静态站。固定入口是 `/remoteops/v1/index.json`，与 RemoteOps 线协议版本分开演进。清单的机器约束见 [JSON Schema](resource-tools-v1.schema.json)，可发布样例位于 `examples/resource-site/remoteops/v1/index.json`。普通未知字段忽略，未知 `schema_version`、`startup.interface` 拒绝执行。

## 部署与校验

在发布机运行 `python scripts/build-resource-packages.py`，输出到 `artifacts/resource-candidates/site/remoteops/v1`。将 `site` 作为 HTTPS 静态站根目录；修改清单发布者、说明与平台测试信息后再发布。样例中的包大小和 SHA-256 来自本次真实候选，ZIP 不写入 Git，文件名包含内容摘要；发布应只复制最终清单引用的包，避免包含历史候选。可将整站复制到不同域名，包地址相对清单解析，不需要改代码。

```powershell
cargo run -p remoteops-resources --bin resource-manifest-check -- examples/resource-site/remoteops/v1/index.json
```

旧版 Agent 及独立资源运行时默认关闭资源工具，启用时显式配置完整清单地址和允许来源。新版集中模式从已认证中继取得目录，不读取下面的旧发现配置：

```json
{
  "resource_tools": {
    "index_url": "https://resources.example.org/remoteops/v1/index.json",
    "allowed_origins": ["https://resources.example.org", "https://downloads.example.net"]
  }
}
```

允许来源必须只包含 HTTPS 协议、主机和可选端口，不含路径、查询、片段或用户信息。清单和包的每一次重定向都重新检查此本地白名单；最多五次重定向。清单不能增加信任源。跨来源包下载只有显式加入本地白名单后才允许。

## 清单字段

每项工具包含 `id`、精确 `version`、`description`、`capabilities`、`documentation_url`、`publisher`、`license`、`limitations`、`release_notes`、`permissions`、`requires_desktop`、`platforms`、`package`、`startup`、`health_check` 和 `timeout_secs`。

`capabilities` 和 `permissions` 是供 AI 选择候选的说明，不能授予权限。启动外部工具与每次调用均沿用 RemoteOps 高风险操作检查；不信任上游声称只读。`documentation_url` 和包 URL 可以相对清单；文档链接仅展示，不自动执行其内容。

`platforms` 每项包含 `os`、`arch`、`os_versions` 和 `status`（`passed`、`pending`、`unsupported`）。仅匹配本机 OS/架构且标记 `passed` 才允许启动。Windows 还必须包含 `min_windows_build` 和 `max_windows_build`，本机通过系统注册表取得的 build 必须在范围内；建议仅登记实际测试的 build。人类可读 `os_versions` 不参与模糊匹配。缺少范围、未知系统和待测组合一律拒绝。`requires_desktop=true` 还需系统事实确认当前具有普通交互输入桌面，服务、锁屏和未知状态不通过。

`package` 必须为 ZIP，声明 HTTPS 或相对 `url`、精确字节数 `size`、小写 64 位 `sha256`。最大下载 1 GiB、最大解压 4 GiB、最多 100000 条目、单条最大压缩比 500；拒绝绝对路径、`..`、Windows 设备名/备用流、反斜线、链接、重解析点、重复文件与大小写别名。损坏缓存拒绝启动，不在后台执行不受控修复。

工具中心新增或变更浏览器 MCP 启动配置时，非空浏览器路径要求显式 `browser_adapter`（`playwright` / `agent_browser`），否则返回 `browser_adapter_required`。既有登记不自动迁移，纯说明修改和旧目录加载保持兼容；省略适配字段且浏览器路径非空仍按 Playwright 处理。

`startup.executable` 及非空的 `browser_executable` 必须是包内相对路径；Windows 必须为原生 `.exe`，拒绝可能触发隐式 Shell 的批处理文件。通用 MCP 与 CLI 的 `browser_executable` 可以省略或留空。`args` 是直接传给进程的参数数组，不经过 Shell；只支持 `${package}`、`${run}`、`${profile}` 路径占位符。环境变量清空，仅保留系统运行库所需白名单；HOME、临时目录、配置目录、browser profile 与 agent-browser socket 全部指向独立运行目录。包应自行包含运行所需依赖。

## 缓存与生命周期

清单使用 ETag 和 Last-Modified 条件请求，缓存绑定完整清单 URL；站点切换不会重用其他来源的清单响应。进程正在运行时固定其版本及摘要。包以摘要命名，校验大小和 SHA-256 后在同一磁盘临时目录解压，原子重命名提交。并发准备复用同一缓存，跨进程提交竞态只接受校验通过的赢家。启动前再次校验保留的原始 ZIP SHA-256，并将整个展开目录与原始 ZIP 的逐文件摘要比对；本地完整性记录不能独自决定可信。

大包解压和完整性扫描在阻塞工作线程运行，避免占用 Agent 异步运行时。取消期间已启动的缓存工作最多完成当前有界准备工作，不会继续启动工具。包缓存保留；运行目录和 profile 随实例销毁。每个实例至多同时执行一个调用，实例绑定 RemoteOps 会话，不能跨会话调用或停止。每个管理器最多八个实例。

Windows 进程以暂停状态创建，先加入共享 Job 再恢复，且不允许子进程脱离 Job；关闭实例时终止整个进程树。agent-browser 的后台 daemon 与后续 CLI 共享实例 Job，不因单条 CLI 正常退出而丢失浏览器状态。首版 agent-browser CLI 仅支持 Windows。停止、断线、取消、未知结果和 Agent 退出都会回收实例。显式停止先请求自有浏览器关闭，再终止进程树并回收临时目录；系统句柄短暂占用时登记最多 60 秒的后台清理任务。`stop_session`、`stop_all` 等待已取消的启动退出并等待登记的清理任务，超时或仍有占用返回 `cleanup_pending`，不能报告已完成清理。Future 被强制取消时 Drop 先杀进程并登记清理，管理器退出时在无持锁的状态下等待任务；GUI 必须等待后台 worker 实际结束后再关闭进程。

## 调用接口

显式浏览器适配与诊断契约见 [浏览器启动说明](../deploy/skills/remoteops/references/browser-startup.md)。`startup.browser_adapter` 可选 `none`、`playwright`、`agent_browser`；省略/null 保留旧行为。显式模式必须使用声明 `resource_tools_browser_adapters_v1` 的 Agent，并配套新版 Relay 能力检查；不能通过旧 Agent 忽略字段继续执行。

`stdio_mcp` 支持通用逐行 STDIO MCP：启动后执行标准 `initialize`、`notifications/initialized`、`tools/list`，返回实际 `inputSchema`，调用通过 `tools/call`。省略/null 适配字段时，`startup.browser_executable` 留空则不附加浏览器参数、不调用浏览器探针；填写浏览器路径则沿用 Playwright 适配，以新建的独立 profile 打开固定 `about:blank`。显式 `agent_browser` 改为环境变量注入，显式 `none` 要求空浏览器路径。STDIO 为逐行 JSON-RPC，不开放网络 MCP 端口，不提供 sampling、elicitation 或 roots。总响应上限 4 MiB，上游未支持的方法返回拒绝。初始化最大 120 秒，单次调用最大 300 秒。

`agent_browser_cli` 提供 `browser_open(url)`、`browser_snapshot()`、`browser_click(ref)`、`browser_fill(ref,text)`、`browser_eval(script)`、`browser_close()` 六个结构化调用。实例直接执行固定原生 exe，追加 `--json`、独立 session/profile、固定 browser 路径后再追加操作参数。拒绝未知字段、参数类型错误、NUL、非 `@` 元素引用，以及以 `-` 开头的字符串参数，避免上游将内容解释为全局选项。需要输入以 `-` 开头的内容时可通过已授权的 `browser_eval` 脚本设置；脚本本身同样不能以 `-` 开头。首版不暴露 attach、CDP、现有 profile、认证仓库、插件安装或任意 CLI 参数。

启动诊断新增可选 `launch_context`，记录接口、最终适配模式、来源和适配器追加参数（路径占位符）及环境变量名，不返回完整命令行或变量值；旧记录可缺失。

工具启动前失败返回 `retry_safe=true` 和固定错误类别，AI 可以据此选择其他兼容候选。提交用户操作后发生超时、取消、连接中断、输出超限或解析失败，返回 `result_unknown`、`retry_safe=false` 并销毁实例。上游明确报告的执行错误也不自动重放。调用方必须保留操作和结果记录，先核实实际状态，再决定后续操作。版本固定的 agent-browser 0.41.2 上游只在连接尚未建立时重建 daemon，不在已写入请求或丢失响应后重放；RemoteOps 不增加额外重试。

## 固定候选与信任边界

| 后端 | 固定输入 | 当前发布状态 |
| --- | --- | --- |
| Playwright MCP | Node 22.23.4、MCP 0.0.84、Playwright/Core 1.65.0-alpha-2026-10-30、Chromium revision 1252（CfT 157.0.8103.15） | 实验候选，包含预发布依赖 |
| agent-browser | 原生 Windows x64 0.41.2、CfT 157.0.8103.38 | 实验候选 |

发布脚本按固定 URL 下载，校验 Node 官方 SHA-256 和 npm SHA-512 integrity，输出每个输入的 URL/大小/SHA-256 锁文件；npm 包按固定版本解包，不运行安装脚本，也不查询 latest。许可证与锁文件保留在包内；CfT 官方 ZIP 不包含独立 LICENSE，发布机直接从固定浏览器的 DataPack v5 提取 `resources.pak` 的 credits（Brotli）和 `locales/en-US.pak` 的附加条款（gzip），保留原 HTML、文本、归档摘要、源文件摘要及资源 ID，不启动浏览器。附加条款引用的 Google 主条款仍是外链，不将其宣称为固定版本快照。CfT 条款以包内 `LicenseRef-Chrome-for-Testing` 内嵌文本及官方页面为准。浏览器来自固定官方版本 URL，首次获取的内容摘要记入输入锁文件；后续同 URL 内容变化拒绝打包。不同来源所维护的校验值本身仍依赖该 HTTPS 来源的完整性。

首版没有强制发布者签名。用户配置的来源被攻破时，攻击者能够发布可执行代码并替换清单摘要；HTTPS 和摘要只能保证来源与下载完整性，不能替代对发布者的信任。运行目录隔离也不是针对恶意可执行文件的沙箱。只应允许自己愿意在 Agent 权限下执行其软件的资源站。

## 中继集中目录与通用 CLI

工具数据库格式 2 从格式 1 原位迁移，增加默认空的 `guide_markdown`，保留工具、包、审计和请求记录。管理者通过 `set_guide` 更新最多 32 KiB UTF-8 的全局说明，沿用权限、修订和幂等机制；说明随认证目录同步，`list_resource_tools` 同时返回说明及候选。仅修改指引不终止仍被允许的实例；旧目录缺少该字段按空说明处理。说明不能授予权限或允许结果未知时重放。数据库升级后回滚旧 Relay 需恢复升级前的完整备份，不能让旧程序直接打开格式 2 数据库。

新版 Agent 使用 `ResourceManager::new_centralized`，默认关闭，目录及策略只来自当前已认证中继连接。旧本地资源站字段保留给旧组件；集中模式不会读取旧字段以绕过中继开关。目录接收任务逐条同步发布修订及取消信号，再异步清理实例，连续关闭、开启的消息不能被合并成无停用。新认证连接会清空目录及修订，不接受上一连接的离线目录。中继托管地址为 `relay://packages/<sha256>.zip`，通过注入的认证分块下载通道取得临时 ZIP；外部 HTTPS 包由 Agent 直连下载。两者继续复用固定摘要缓存、原始 ZIP 复核、平台门禁和会话隔离。

`startup.interface="cli"` 声明通用原生 CLI，`browser_executable` 留空，`health_check.method="schema"`；启动只验证登记定义及包完整性，不宣称已在平台执行成功。`startup.operations` 每项包含 `name`、`description`、`input_schema`、`args` 和 `result_format`（`text` 或 `json`，默认 `text`）。`args` 项为 `{ "kind":"literal", "value":"--version" }` 固定参数，或 `{ "kind":"parameter", "name":"text" }` 读取一个顶层参数。输入 Schema 使用对象类型，不允许引用；关闭远程引用获取。映射字段必须在 `properties` 登记，调用前验证类型、必填、枚举等约束；字段值仅接受字符串、数值或布尔值，作为单个 argv 传递，不拼接 Shell。工具作者应使用自身支持的参数分隔符防止选项歧义。

每次 CLI 调用独立创建受管进程，返回 `exit_code`、UTF-8 `stdout`、`stderr` 和解析后的 `result`。非零退出码仍返回确认的进程结果；输出总量限制为 4 MiB。超时、取消、断线、输出超限或 JSON 解析失败返回 `result_unknown`，禁止自动重放并终止进程树。Schema 校验通过与文件校验通过均不替代真实平台测试。

CLI 操作可通过可选 `executable` 指定另一个包内原生程序，省略时继承 `startup.executable`；同样验证安全相对路径、包内文件及 Windows 原生 EXE 限制。`documentation` 携带工具中心登记的 `name`、`purpose`、`instructions`、`examples`、`dependencies`，供 AI 选择和使用；说明文字不能扩张权限。
