## 一、结论

第一阶段已经完整交付并通过本机与三台真实测试机器验收：

```text
Rust 核心业务类库
+ Linux Docker Relay
+ Windows Agent
+ Controller CLI
+ 本地 STDIO MCP
+ `LAB-AGENT-A`、`LAB-AGENT-B`、Linux Relay 三机端到端验证
```

本阶段没有开发 GUI、远程桌面、图像识别或鼠标键盘自动化。

真实交换机 SSH 和真实 USB/COM 串口读写由于没有现场硬件，仍明确标记为“待现场硬件验证”。项目已经完成 Agent 侧真实 OpenSSH 密钥认证、两台 Windows 的真实串口枚举以及串口打开/读取/写入/关闭实现和自动化测试，未把这些结果夸大为真实交换机 Console 验收。

核心业务只在类库中实现一次：

| 核心类库 | 主要职责 |
|---|---|
| `remoteops-domain` | 标识、连接、租约、能力、远程操作、事件、审批状态和错误 |
| `remoteops-protocol` | Agent、Relay、Controller 消息、帧编解码和 TLS |
| `remoteops-session` | 多连接注册表、默认编号、别名、目标解析和人工接管 |
| `remoteops-policy` | 结构化只读白名单、风险分类、审批记录和一次性消费 |
| `remoteops-audit` | JSONL 审计、SHA-256 和敏感信息脱敏 |
| `remoteops-device` | CMD、PowerShell、持久 Shell、SSH、串口、端口和文件适配 |
| `remoteops-application` | Controller 应用服务、请求生命周期、实时事件和 Relay 客户端 |

壳子职责：

| 壳子 | 主要职责 |
|---|---|
| `remoteops-agent` | Windows 宿主生命周期、主动出站、状态文件、心跳、设备能力执行 |
| `remoteops-relay` | TLS 服务、注册/配对/转发、角色认证、审批和状态持久化 |
| `remoteops-controller-cli` | 参数解析、终端输出、人工操作和自动化入口 |
| `remoteops-controller-mcp` | 官方 Rust MCP SDK 的本地 STDIO 工具壳 |
| `remoteops-mcp-smoke` | 以官方 MCP 客户端验证工具发现、调用、审批和文件边界 |

## 三、核心实现结果

已实现：

- Agent 随机 GUID、状态文件和恢复令牌；
- 固定租约内不变的临时控制码；
- Relay `/data/relay-state.json` 持久化；
- Relay 重启和容器重建后原 GUID、控制码、恢复令牌和 `session_id` 恢复；
- 租约真正到期后旧控制码失效，新注册生成新 `session_id`；
- 默认“连接 1、连接 2”和可修改别名；
- 多 Agent、Human Controller 和 AI Controller 角色隔离；
- 每个远程请求绑定 `session_id`、Controller 身份、Agent 身份和连接代次；
- CMD、Windows PowerShell 5.1 和可选 `pwsh.exe` 探测；
- 持久 Shell、实时输出、取消和 Windows 后代进程回收；
- Agent 本机 OpenSSH 密钥认证和固定 `known_hosts`；
- 串口枚举、参数、打开、异步读取、受控写入和关闭；
- 端口探测；
- 文件上传、下载、覆盖策略和 SHA-256；
- Human/AI 共用事件流；
- 人工接管和人工中断 AI；
- 高风险操作审批；
- AI 修改操作由独立 Human Controller 审批；
- 审批精确绑定操作、会话、Controller 身份和连接代次，且只能消费一次；
- 脱敏 JSONL 审计和按会话导出；
- 本地 STDIO MCP 和工具读写/破坏性注解；
- MCP `transfer-root` 边界和路径逃逸拒绝。
- 三机实验 Controller Token 只通过进程环境和权限为 `0600` 的远程临时环境
  文件传递，不进入 SSH 或 MCP Smoke 命令行；
- `target`、`artifacts`、Agent/Relay 状态文件和审计 JSONL 已加入仓库忽略
  规则，避免构建缓存、运行元数据和凭据载体被误提交。

## 十一、未验证能力和剩余风险

未验证：

- 真实交换机 SSH；
- 真实 USB/COM 串口打开、读写和物理拔插恢复；
- 公网 NAT、多地域 Relay 和高并发容量；
- 代码签名、安装包、自动升级和 GUI。

剩余风险：

- 第一阶段 Relay 是单实例内存转发加本地状态文件，不是高可用集群；
- 小型文件通道已有大小和路径边界，但不等同于大文件分块/断点续传；
- 生产部署需要固定证书生命周期、端口、防火墙和 Controller Token 存储方案；
- `serialport` 使用 MPL-2.0，正式分发前继续保留许可证并复核文件级义务；
- 真实客户现场仍需明确授权、可见提示、停止按钮和操作审批体验。

5. GUI 多连接布局、命令时间线和人工/AI 状态展示；
6. 审批弹窗的风险分级和超时策略；
7. 文件传输大小上限、目录策略和下载覆盖体验；
8. 串口真实硬件实验室；
9. 真实交换机 SSH/Console 验收设备；
10. 是否让自托管 Relay 公网可达，以及是否引入反向代理、域名和正式 TLS 证书；

12. 第一批真实客户试点和停止条件。
