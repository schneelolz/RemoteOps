# 部署与三机验收手册

> 文档状态：实验室三机环境手册。`LAB-AGENT-A`、`LAB-AGENT-B` 和端口 `17443` 仅为公开回归示例，不代表实际部署参数。

- 适用版本：`0.2.0-preview.5`
- 更新日期：2026-08-16

## 一、固定环境

| 角色 | 地址或主机名 | 用途 |
|---|---|---|
| Linux Relay | `192.0.2.10` | Docker Relay 和实验 SSH 服务 |
| Windows Agent A | `LAB-AGENT-A` / `192.0.2.117` | 测试目标 A |
| Windows Agent B | `LAB-AGENT-B` / `192.0.2.118` | 测试目标 B |
| 当前开发机 | 当前 Windows 工作区 | 编译、Controller CLI、MCP 和验收编排 |

凭据不写入本项目。Linux 使用
`$env:USERPROFILE\.ssh\remoteops_lab_runner_ed25519`；Windows 管理凭据由脚本从
Windows Credential Manager 在内存中读取。

## 二、本机验证

```powershell
cd <仓库根目录>
cargo fmt --all -- --check
cargo check --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
.\scripts\Test-LocalE2E.ps1
.\scripts\Build-Windows.ps1
.\scripts\Build-LinuxRelay.ps1
```

本机 E2E 会验证：

- TLS Relay 和 Agent 配对；
- CMD、Windows PowerShell 5.1 和 PowerShell 7 的 UTF-8 中文输出、ANSI 清理及隐藏窗口；
- 真实持久 Shell、`exit`、`close_shell` 和进程状态；
- 实时输出事件；
- 端口探测；
- 1 MiB 分块文件上传下载、每块及完整 SHA-256、嵌套目录、覆盖失败恢复和 16 GiB 上限；
- MCP 运行时配对；
- MCP 持久 Shell；
- MCP 审批和文件传输；
- 审计导出；
- 人工中断 AI；
- Relay 状态文件；
- Relay 进程重启后原控制码和 `session_id` 保持；
- 在线租约过期时控制码暂时拒绝新配对，Agent 使用恢复令牌上线后恢复原控制码和 `session_id`。

`remoteops-application` 和 Relay 单元测试另外验证 Controller 先恢复、Agent 后恢复时的自动重新绑定，以及断线前审批和在途写操作不会自动重放。

## 三、Linux SSH 密钥验证

开发机专用实验公钥应加入专用低权限实验账户的 `authorized_keys`。只授权公钥，
不把 Linux 密码写入脚本。

验证命令：

```powershell
ssh `
  -o BatchMode=yes `
  -o StrictHostKeyChecking=yes `
  -i '<实验室 SSH 私钥路径>' `
  '<实验室用户>@<实验室 Linux 地址>' `
  'printf REMOTEOPS_KEY_LOGIN_OK'
```

固定 ED25519 主机指纹：

```text
SHA256:<由实验室管理员提供并通过独立渠道核对>
```

## 四、一键三机验收

```powershell
cd <仓库根目录>
.\scripts\Build-Windows.ps1
.\scripts\Build-LinuxRelay.ps1
.\scripts\Invoke-LabE2E.ps1 -SkipBuild
```

Linux 根分区在本次验收时空间不足，默认采用预编译 Linux Relay。脚本将实验
工作区、Compose 配置、Relay 数据和临时文件放到：

```text
/dev/shm/remoteops-lab/<运行标识>
```

实验 Relay 固定使用宿主端口 `17443`，避免与正式默认端口 `7443` 混淆。

脚本会执行：

1. 固定校验 Linux SSH 主机指纹；
2. 验证 SSH 密钥登录和 Docker 权限；
3. 构建或在 `-SkipBuild` 模式下验证 Windows Release 产物；
4. 验证预编译 Linux Relay 产物；
5. 将最小部署工作区和预编译 Relay 上传到 Linux `/dev/shm` 独立目录；
6. 使用 `Dockerfile` 和 Compose 启动 Relay；
7. 检查 Relay 健康、日志和证书；
8. 启动独立实验 SSH 容器；
9. 使用 WinRM 将 Agent 和证书部署到 `LAB-AGENT-A`、`LAB-AGENT-B`；
10. 用带运行标识的计划任务启动两个 Agent；
11. 配对“客户 A”和“客户 B”；
12. 验证 CMD、Windows PowerShell、PowerShell 7、持久 Shell 的 `exit`/关闭、端口、分块文件和 SSH；
13. 枚举两台机器上的串口；
14. 验证 AI 审批和人工中断；
15. 使用官方 MCP SDK 验证双连接；
16. 验证 Agent A 单独断线不影响 Agent B；
17. 验证网络恢复时原 `session_id` 保持；
18. 通过 Relay 容器和网络重建验证 Agent 自动重连；
19. 检查 `/data/relay-state.json` 存在、非空且权限为 `0600`；
20. 重启 Relay 容器并验证 Agent GUID、原控制码和原 `session_id` 保持；
21. 验证 Controller 可以使用原控制码重新绑定；
22. 验证 Agent 进程重启后从状态文件恢复原 GUID；
23. 等待离线租约过期，验证 Relay 仍保留 Agent 身份，Agent 使用恢复令牌上线后继续使用原控制码和原 `session_id`；
24. 验证 Controller 先恢复、Agent 后恢复时，同一 Controller/MCP 进程会自动重新绑定；
25. 验证断线前未完成请求明确失败，审批和在途写操作不会在恢复后自动重放；
26. 确认既有 Docker 容器仍然运行；
27. 生成不含配对码和凭据的验收结果；
28. 精确清理本次运行创建的目录、任务、规则、容器、网络和卷。

结果文件：

```text
docs\history\evidence\lab-e2e-result-2026-07-31.json
```

历史 `1.3.0` 三机 CLI/MCP 复验已通过；具体内部运行标识已从公开文档移除。新的验收必须生成独立运行标识，不得复用其他运行的端口或目录。

## 六、GUI 手动配对验收

1. 在本机双击 `%USERPROFILE%\Desktop\RemoteOps实验启动器.exe`；启动器不包含 `--pair`，初始连接列表应为空。
2. 在 `LAB-AGENT-A` 或 `LAB-AGENT-B` 双击桌面的 `查看 RemoteOps 控制码.exe`，复制本机当前控制码。
3. 在 GUI 左侧“连接”标题右侧点击 `+`，输入控制码和可选客户名称，点击“连接”。
4. 配对成功后只显示刚添加的 Agent；重复步骤 2-3 添加另一台机器。

控制码只在各自 Windows 桌面本地读取和显示，不写入项目、聊天或验收结果。

## 五、Relay 手工部署

正式或磁盘空间充足环境可从源码构建，默认业务端口为 `7443`：

```bash
cd "$HOME/remoteops-lab/<运行编号>/workspace"
REMOTEOPS_LEASE_SECONDS=600 \
docker compose \
  -p remoteops-relay-<运行编号> \
  -f deploy/relay/docker-compose.yml \
  up -d --build
```

检查：

```bash
docker inspect --format '{{.State.Health.Status}}' remoteops-relay-<运行编号>
docker logs --tail 100 remoteops-relay-<运行编号>
docker ps --filter name=remoteops-relay-<运行编号>
```

正式默认业务端口为 `7443`。自动三机实验固定使用 `17443`，健康检查由脚本
直接在容器内执行，不额外占用固定宿主健康端口。

Relay 状态文件为：

```text
/data/relay-state.json
```

状态文件保存在独立 Docker Volume 中，包含可恢复的 Agent 身份、控制码租约、逻辑 `session_id`、连接代次和已确认恢复令牌。在线租约过期后，Relay 将 Agent 标记为离线但不删除这些恢复信息；Agent 以后使用有效恢复令牌重新认证时会续租并恢复原身份。Controller 连接、审批和在途请求不会跨 Relay 重启恢复，也不会自动重放。状态文件损坏、格式版本不支持或包含重复身份时，Relay 会拒绝启动。

## 六、Windows Agent 手工启动

```powershell
.\remoteops-agent.exe `
  --relay 192.0.2.10:7443 `
  --server-name 192.0.2.10 `
  --ca-cert .\relay-cert.pem `
  --state-file .\agent-state.json `
  --retry-seconds 1
```

Agent 启动后显示：

- Agent GUID；
- 临时控制码；
- 控制码租约到期时间；
- Relay 连接状态。

Agent 状态文件保存随机生成的 GUID 和最近确认的恢复令牌。不要删除、复制给无关人员或加入源码仓库；删除该文件会使 Agent 以新现场实例重新注册。

客户随时关闭 Agent 即可终止远程协助。

## 七、清理边界

自动脚本只在以下实验目录和对象内工作：

- Linux 预编译模式：`/dev/shm/remoteops-lab/<运行标识>`；
- Linux 源码构建模式：`$HOME/remoteops-lab/<运行标识>`；
- Windows：`C:\ProgramData\RemoteOpsLab\<运行标识>`；
- Windows 计划任务：`RemoteOpsLabAgent-<运行标识>`；
- 临时防火墙规则：`RemoteOpsLab-Temporary-Block-<运行标识>`；
- Docker 容器：`remoteops-relay-<运行标识>`、`remoteops-lab-ssh-<运行标识>`；
- Docker Compose 项目：`remoteops-relay-<运行标识>`、`remoteops-lab-ssh-<运行标识>`；
- Docker Volume：`remoteops-relay-data-<运行标识>`。

脚本不会执行 `sudo`，不会修改 RemoteOps 之外的既有服务，也不会删除其他容器和数据卷。
实验 Controller Token 只在内存和权限为 `0600` 的远程临时环境文件中传递，
不作为 SSH 或 MCP Smoke 的命令行参数；远程文件随运行目录一起清理。

如果某次执行被外部中断，可使用运行标识进行受控清理：

```powershell
.\scripts\Invoke-LabE2E.ps1 `
  `
  -CleanupRunToken '<运行标识>'
```

清理逻辑只匹配该运行标识创建的资源，不执行全局 Docker prune。
