## Windows 软件渲染与 UIA 可行性

计划采用 `default-features=false`，显式启用 `std`、`compat-1-18`、`backend-winit`、`renderer-software`、`accessibility`、`unstable-winit-030`，运行后端为 `winit-software`。软件渲染不要求 GPU；无障碍由 winit 后端的 AccessKit 适配处理，不能为缩小体积遗漏 `accessibility`。[winit 后端与渲染器](https://docs.slint.dev/latest/docs/slint/guide/backends-and-renderers/backend_winit/)、[1.18.1 feature 定义](https://github.com/slint-ui/slint/blob/v1.18.1/api/rs/slint/Cargo.toml)。最终必须再核对实际锁文件与构建 features，不能用计划代替产物事实。

1.18.1 的 winit 适配源码已经包含以下路径：

- `AccessibleStringProperty::Id` 映射到 AccessKit `author_id`。
- `ReadOnly` 映射到只读状态。
- 默认动作映射到 Click，文本输入可发出文本子树。

这给 UIA AutomationId、Invoke、Value/TextPattern 提供实现基础；不保证具体候选中的自定义组件已经正确声明，也不等于中文、大量日志、焦点或退出已经通过。[1.18.1 winit AccessKit 实现](https://github.com/slint-ui/slint/blob/v1.18.1/internal/backends/winit/accesskit.rs)。

Slint 的控件通常是虚拟节点，`NativeWindowHandle` 可以为零。独立 Slint 客户端只从已校验 PID/启动时间/SHA256/ProductName 的顶窗向下查询，不用 Win32 子控件 HWND 或 `TreeScope.Children` 限制来误判。它记录真实 AutomationId、角色、支持的模式和只读属性；缺失模式必须失败或明确待验，不用按钮看起来可点来代替 Invoke 支持。数字 label 前缀只作为明确标记的兼容定位，不宣称等同 AutomationId。

只读日志应由真实只读 TextEdit 提供完整文本及 `accessible-read-only` 语义。静态状态标签、控件标题或截图不能冒充日志全文。自定义按钮应声明可访问角色、标签、ID 与默认动作，动态文字不能被固定标签遮盖。[Slint 无障碍属性](https://docs.slint.dev/latest/docs/slint/reference/common/)、[自定义组件无障碍建议](https://docs.slint.dev/latest/docs/slint/guide/development/best-practices/#accessibility)。

## 两版共同验收口径

两版共用 core/host 不代表两版 UI 自动等价。先核对绑定到同一事实/动作，再执行同口径验收。

| 项目 | 必须提供的实际证据 | Slint 当前状态 |
| --- | --- | --- |
| 主窗、控制码、复制 | 真实 UIA 控件、受控 Relay 签发码；复制接受不等于成功 | 开发候选的演示与复制反馈已验；真实 Relay 待验 |
| 首次设置、偏好 | 中文输入、保存/取消、语言主题及草稿保持 | 待候选实测 |
| TLS | 未信任前不签发可复制码；取消、仅本次、保存及重启 | 待真实回环验收 |
| 权限 | 无控制端禁用；真实取消/确认；Relay 回执模式/来源一致 | 待真实回环验收 |
| 详情、日志 | 真实只读属性、完整正文、筛选/清空、更新及未读 | 开发候选详情只读已验；日志功能尚未到达 |
| 操作观察 | 同一观察窗显示首帧、中文/emoji、stderr、末帧 | 待真实命令验收 |
| 密码隐藏 | 仅随机合成值参与测试，断言不可出现在观察/日志/报告 | 待真实命令验收 |
| 隐藏、重开、焦点 | 隐藏不停止任务，重开有末尾；稳定基线前后 HWND 相等 | 开发候选首次显示激活失败，修复后待重验 |
| 退出 | 正常确认、有界退出、后台停止、报告与真实结果一致 | 待候选实测 |
| 体积与性能 | 固定 SHA256 下的 EXE/侧工具大小、实际 UI 更新指标 | 待统一构建测量 |
| 高分屏、RDP | 真实系统缩放与真实断开重连；不能用注入值替代 | 本轮未执行 |
| SSH、串口现场 | 真实目标与已核对主机密钥/串口设备 | 本轮未执行 |

## 独立测试与安全边界

新增 Slint 测试文件与原 Win32 测试分开；不覆盖历史失败或修改原通过条件。所有缓存/临时 profile 位于 C 盘。测试只操作自己启动或传入精确身份的 Slint 预览进程，不操作旧程序、RDP、系统缩放或现场 Agent。

GUI 客户端：`scripts/Test-SlintGuiClient.ps1`。每次动作重新核验进程身份；Snapshot 原始文字仅供父 runner 内存断言，正式报告只收固定检查名、布尔、数值与安全分类。截图只能捕获该测试自己的窗口，真实回环码不写入报告。

演示/首次设置：`scripts/Test-SlintGuiProduct.ps1 -Executable <Slint EXE> -ExpectedHash <SHA256> -OutputDirectory <全新C盘TEMP目录>`。真实回环：`node scripts/test-slint-ui-e2e.mjs --agent <Slint EXE> --relay <Relay EXE> --mcp <MCP EXE> --ui-client <Test-SlintGuiClient.ps1> --output <全新C盘TEMP报告.json>`；默认包括 TLS，`--scenario operations` 只略过单独 TLS 流程，不略过权限和真实输出验收。权限及退出确认是主窗内 Slint 确认层，使用 400/401 的真实 Invoke，不沿用 Win32 MessageBox 实现。

Slint 当前报告提供 `max_tick_ms`，但仅覆盖应用 timer 工作，不含实际栅格渲染；没有 Win32 的 `pending_units`、`view_caught_up`、最终控件/模型逐字一致等指标。独立回环脚本以真实 UIA 正文末行/只读、后端标识和共享 host 退出为证，不把缺失字段视为零。报告明确保留这些限制，不能拿两个前端不同定义的同名 timer 数值直接宣称渲染性能胜负。

### 更新与呈现频率不同

| 口径 | Win32 现实现 | Slint 现实现 |
| --- | --- | --- |
| 连续输出显示合并间隔 | `log_view.rs` 的 `STREAM_FRAME_INTERVAL=33ms` | `app.rs` 的 `FRAME_INTERVAL=100ms`，首次/自动打开等路径可立即提交 |
| Slint host 轮询 | 不适用此实现 | 应用 timer 每 25ms 运行；不等于每次都呈现新帧 |
| 同名耗时指标 | Win32 消息/控件更新工作，具体包括的步骤见其报告 | 应用 timer/属性更新工作，不包括随后实际栅格绘制 |

100ms 与 33ms 是有界合并/提交策略，不是固定实测帧率；也不是整个业务接收/传输的丢失统计。频率不同会影响刷新次数和单次工作量，不能据 Slint 的 timer 数值小就宣布优胜。目标并非强行使两个前端频率相同，而是核对交互是否及时、真实首帧/尾行能否看到、UIA 是否可用、退出是否稳定，再结合可比口径的体积与实际体验评估。
